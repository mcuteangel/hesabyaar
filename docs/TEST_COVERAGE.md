# Test Coverage Scope and Methodology

This document describes the test coverage architecture for Hesabyar.

## Kotlin and Android Coverage

Kotlin test coverage uses JaCoCo.
The authoritative configuration is `gradle/jacoco-coverage.gradle.kts`.
The report path is `app/build/reports/jacoco/jacocoTestReport/jacocoTestReport.xml`.
The task runs all unit tests and isolated Rust-bridge JNI tests.

### Excluded Classes

JaCoCo excludes generated code and build boilerplate from the report denominator:
- Android resource classes (`R.class`, `R$*.class`)
- Build configuration classes (`BuildConfig.*`)
- Android manifests (`Manifest*.*`)
- Room generated DAO and database implementations (`*_Impl.class`, `*_Impl$*.class`)
- Hilt and Dagger generated code (`*_HiltModules*.*`, `*_Factory*.*`, `*_MembersInjector*.*`, `Hilt_*.*`, `DaggerHesabyarApp*.*`, `HesabyarApp_HiltComponents*.*`, `hilt_aggregated_deps/**`)
- UniFFI generated file facades (`hesabyar_core*.*`, `Hesabyar_core*.*`, `Uniffi*.*`, `FfiConverter*.*`)

The UniFFI package `io.github.mojri.hesabyar.rust` needs a stronger rule.
The generated `hesabyar_core.kt` produces top-level classes such as `Transaction`,
`AnalyticsData`, and `RustBuffer`. Their names change with the FFI surface.
A name-based exclusion list would drift. The configuration therefore keeps only
the hand-written bridge classes in that package: files that start with
`RustBridge` or `RustMappers`. The `gradle/jacoco-coverage.gradle.kts` file is
the single source of truth for all exclusion patterns.

### Included Classes

Hand-written application source files remain included:
- Domain models and UseCases
- ViewModels and UI state formatters
- Repository implementations and Room DAOs
- Hand-written Rust bridge classes (`RustBridge.kt`, `RustMappers.kt`)

## Rust Core Coverage

Rust core coverage tests the `rust` workspace.
CI generates LCOV coverage with `cargo-llvm-cov nextest --workspace`.
The report path is `rust/lcov.info`.
The workflow prefixes every workspace-relative LCOV path with `rust/`.
The prefixed file `rust/lcov.prefixed.info` feeds Codacy and DeepSource.
Codecov, Coveralls, Qlty Cloud, and BuildPulse consume `rust/lcov.info`.
Only Qlty configures path handling (`add-prefix: rust`).

## Metrics Interpretation

Codacy aggregates both reports into one project-wide percentage.
There is no per-language percentage in Codacy.
The combined number mixes Kotlin/JVM and Rust sources.
The reported value is weighted by the language with more reportable lines.
The real effect of this change has two parts:
1. The Kotlin denominator no longer counts generated bytecode.
2. Rust coverage is now visible in Codacy.

Do not treat the merged percentage as a per-language quality gate.
